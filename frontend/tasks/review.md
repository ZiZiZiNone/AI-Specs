# Review 任务

问题、风险、建议、依据。

## 授权面：只读（COM-012）

Review 全程不修改代码，包括发现的明显笔误、失效代码与低风险改动——
它们写进「问题」表格，由用户决定是否修。

允许的动作：读文件、检索、执行只读白名单命令、输出报告（指对话内报告）。
只读白名单（仅允许以下只读形式，按项目实际取用）：
- 类型检查：`vue-tsc --noEmit`
- Lint：`eslint . --no-fix`（或 `eslint <范围> --no-fix`，结果摘录粘贴）
- 测试：`vitest run <范围> --coverage=false`（结果摘录粘贴；构建如需验证用只读构建命令，不加写参数）
禁止的动作：写文件（含把报告落盘成文件）、`--fix` 类改写参数、格式化、删除、提交、安装依赖。
报告需落盘时，另起任务并重新声明授权面。

用户在看到报告后要求修改时，任务类型按 `common/protocol/task-analysis.md` 重新判定
（改行为→Bugfix，只调结构→Refactor），并声明新的授权面。不要在同一轮里边审边改。

判据与四类越界见 `common/protocol/task-boundary.md`。

## 输出
- 问题：按严重度列出的具体问题（含文件/位置）。
- 风险：潜在缺陷与影响范围。
- 建议：可执行的改进建议。
- 依据：每条结论给出对应规范/代码依据。
- 评分（可选）：按四维各 0-5 打分，附失分原因。

## 评分标准（每维 0-5，总分 = 各项均值）
- 架构：页面厚度 / 分层合规 / 依赖方向 / 职责单一。
- 一致性：命名风格 / 模式套用 / 结构统一 / 规范遵守。
- 可维护性：可读性 / 可测试性 / 可复用性 / 变更成本。
- 状态：范围合理 / 来源单一 / 无冗余 / 生命周期。

## 规则
- 结论有据可查，不做无依据评价。
- 区分"确定问题"与"建议改进"。
- 引用规范条款前打开原文核对（COM-011）：见 `common/rules/constitution.md`「编号 + 文件路径 + 原文逐字摘录」。
- 报"规范未覆盖"须附检索命令与空结果（COM-011）：见 `common/rules/constitution.md`「附检索命令与空结果」。
- 同一事实取证一次即止，不重复检索与重跑（见 `common/protocol/task-boundary.md`「重复取证」）。
