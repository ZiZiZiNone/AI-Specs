# 全局化

对齐关系见 `frontend/rules/core-principles.md`「FE-104 单向数据流原则」，本文件讲状态归属最小化，范围能小不放大。

## 定义

不区分共享范围、把局部状态一律放入 Store 即为全局化。

## 判定信号

### 可观测信号（引用 `frontend/rules/core-principles.md` 原文数字，保持全库一致）

- 全库统一阈值：页面 300 行 / 函数 3 个 / 状态 5 个；组件 300 行 / props 8 个；Hook 150 行 / 成员 10 个；“禁止以搬运换达标”。

- 页面内状态变量“不超过 5 个”，超量先审视归属而非直接全局化。

- 父子共享层级不超过 2 层、兄弟共享有共同父组件且不超 3 层，否则才考虑上移。

- 仅跨页面或跨模块共享进入 Store，其余逐级下放，判据见“状态归属决策”。

- 组件“禁止直接 import Store”“禁止访问路由参数/全局变量”，自包含交互组件白名单除外。

### 症状（命中 2 条即进入对策）

- Store 膨胀：仅一处使用的状态也进全局，组件过度订阅。

- 状态来源不清：同一状态多处写入，更新不走明确入口。

- 受控组件另存 props 副本，与外部形成双写入点，外部重置不生效。

- 需刷新保持的筛选分页放组件 state，刷新即丢；或反之全塞 Store。

## 对策（拆到哪层，四选一写明）

- 仅单组件用 → 组件内局部状态，不进 Store 不上移。

- 父子 / 兄弟共享 → 共同父组件：props 下发、回调上报，层级内解决。

- 需刷新保持 → URL 参数：筛选 / 分页 / 排序以 URL 为唯一来源。

- 真跨页跨模块 → Store：经明确 action 读写，配 selector 实时派生。

- 候选并列（交用户定）：A. 筛选放 URL；B. 筛存放 Store 持久化。刷新语义不同，选用由用户定。

## 正例指针

- `frontend/examples/golden/list-page.md`「1. 筛选条件以 URL 为唯一来源」：筛选以 URL 为唯一来源，组件全受控只上报变更。

- `frontend/examples/golden/list-page.md`「6. 页面只做组装」：页面向下传原始数据，向上经回调收结果；表格不自持业务状态，给什么渲染什么。

## 反例指针（`frontend/examples/golden/anti-examples.md`，标题原文引用，不编新条号）

- 「6. 受控组件自持一份状态」：三份 state 与 URL 双写。

- 「2. 展示型组件自己加载数据」：错误态埋组件内页面无法感知。

- 「9. useEffect 依赖注释掩盖问题」：对象无稳定标识致只能挂错依赖。

## 自检指针（`frontend/checklists/detailed-check.md`，用小节名）

- “状态归属”：局部 / 父级 / URL / Store 四档各就其位，范围最小化。

- “状态来源”：来源单一、无 props 副本、无隐藏修改三项。

- “全局化”：未把所有状态放入 Store，遵循状态归属决策。

- “派生状态”：能计算的不存储，用 selector 与计算属性实时算。

## 决策指针（`frontend/protocol/decision-trees.md`，指针短语）

- “状态归属决策”：单组件→父子→兄弟→跨页逐级问，否即重审是否真需共享。

- “组件自持状态决策”：业务组件、复合组件、涉数据请求一律经 props。
