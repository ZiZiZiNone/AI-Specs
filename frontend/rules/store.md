# Store

Store只存共享状态，不承载业务逻辑。

## 状态归属决策
1. 只在单个组件内使用 → 组件内局部状态。
2. 父子/兄弟需要共享 → 提升到父组件，props/回调下发。
3. **需要刷新后保持** → **URL 参数（持久化状态）**。
   - 列表筛选条件
   - 分页参数（page/pageSize）
   - Tab 索引
   - 搜索关键词
   - 排序条件
4. 跨页面/跨模块或多处需要响应式共享 → 进入 Store。

每上移一级都先确认必要性，避免提前全局化。

## 规则
- 只放跨组件/跨页面共享、且需要响应式更新的状态。
- 组件内/父子间局部状态留在本地，不塞进 Store。
- Store 只做状态读写与 action 编排，不写业务判断、不转换数据。
- Store 的 action 可调用 Service 加载「该 Store 自身拥有的状态」
  （会话、当前用户与权限、全局配置、未读数等）。
- **禁止**在 Store 里加载页面业务数据（列表/详情/表单），那属于 Hook 的职责。
- 派生值实时计算（selector/计算属性），不冗余存一份。
- 更新走统一入口（action/mutation/setter），避免散落的直接修改。

### 为什么页面数据不能进 Store
Store 的生命周期与应用同寿，页面数据的生命周期跟随页面进出。
把列表/详情放进 Store 会让二者脱钩——离开页面数据仍在，
再次进入时可能先读到上一次的残留，且并发页面互相覆盖。

```
问：这份状态归 Store 还是 Hook？
  ├─ 应用级、跨页面、跟随会话（当前用户、权限、全局配置、未读数）
  │    → Store，加载写在 Store 的 action 里
  └─ 页面级、跟随页面进出（列表数据、详情、表单）
       → Hook，Store 不参与
```
