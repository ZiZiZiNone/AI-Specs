# 前端国际化、时区与数值精度规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 1. 金额与高精度计算（对齐 `common/rules/business-rule.md`）
- 前端严禁使用 JS `number` 浮点数直接做金额加减乘除（如 `0.1 + 0.2 !== 0.3`）；
- 接口统一传输整数分（`*Cents`）或定点数字符串，前端展示时仅在视图格式化层转换为货币字符串（使用 `Intl.NumberFormat`），涉及前端试算必须以整数分运算或使用定点数库。
- 超出 `Number.MAX_SAFE_INTEGER`（2^53 - 1）的 64 位长整型 ID（如雪花 ID）必须以 `string` 传输与存储，禁止转成 `number` 导致末尾精度丢失。

## 2. 时区与日期格式
- 接口传输与存储统一采用 **ISO-8601 UTC 字符串**（如 `2026-11-23T08:00:00Z`）或明确单位的 Unix 毫秒时间戳（`*AtMs`）；
- 严禁把无时区偏移的本地字符串（如 `"2026-11-23 08:00:00"`）直接传给 `new Date(...)`（跨浏览器/Safari 解析不一致）；
- 展示层统一通过 `Intl.DateTimeFormat` 或项目统一时间工具按用户时区格式化。

## 3. 国际化（i18n）边界
- 需要多语言的项目严禁在业务组件内硬编码中文/英文拼接句（如 `'共 ' + n + ' 条'`），应使用带参数占位与复数支持的翻译键；
- 布局须兼容长文案（德语/英文通常比中文长 30%–50%），按钮与表头预留截断/换行策略。

## 检查清单

- [ ] 金额计算未用裸 JS 浮点，64 位长 ID 均用 `string` 处理
- [ ] 无 `new Date("YYYY-MM-DD HH:mm:ss")` 非标准解析
- [ ] 货币与日期展示使用统一格式化工具
