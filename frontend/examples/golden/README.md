# Golden Example

示例必须来自已落地并通过自检的代码；项目一致性高于个人偏好。

## 示例来源（可用范围）
按可信度排序，任一即可作为素材：

1. 真实业务项目中已上线、经审阅的代码。
2. **本目录自包含示例即载体，不依赖已删除的 `frontend/test/` 工程。**
3. 从上述两类中提取的违规片段（作为负向示例）。

**禁止**：凭想象编写从未落地的"理想代码"；脱离真实约束的教学式伪示例。

## 示例规则
- 每个示例标注来源文件路径、示范的规范条目。
- 正向示例须能指出它解决了什么具体问题；负向示例须给出"正确做法"。
- 示例代码可裁剪（省略无关分支），但不得改写成从未写出过的形态。

## 示例教什么、不教什么

**示例的判定对象是结构**：分层归属、依赖方向、状态归属、数据流向、职责边界。
这些靠阅读即可判定，与代码是否运行过无关。

因此**不要求**示例来源已通过构建/测试。但两类结论须区别对待：

| 结论类型 | 可信依据 | 举例 |
|---|---|---|
| 结构类 | 阅读即可判定 | 页面不直连 Service；筛选条件以 URL 为唯一来源；Logic 不 import 框架 |
| 机制类 | 依赖语言/框架语义，静态推演可能出错 | composable 参数用 `Readonly<Ref<T>>`（因 `ComputedRef` 赋不进 `Ref<T>`）；viewModel 用 `computed` 而非嵌套 `reactive`（代理身份问题） |

**机制类结论须在示例中写明其成立理由**（如上表括号内容），使读者能自行复核；
若该理由未经实际验证，注明「结论依据为静态推演」。结构类结论无需此标注。

**禁止**：凭想象编写从未落地的"理想代码"；脱离真实约束的教学式伪示例；
把未在来源项目中出现过的函数名/接口冒充为来源代码。

## 现有示例
- `frontend/examples/golden/list-page.md`：列表页（URL 状态、竞态、刷新保留数据、乐观更新）
- `frontend/examples/golden/form-validation.md`：表单三段校验、异步唯一性、动态可见性
- `frontend/examples/golden/service-layer.md`：统一请求出口、错误归一、幂等重试
- `frontend/examples/golden/anti-examples.md`：负向示例集（本文件内联反例）

## 风格指南
- 优先遵循项目既有风格与约定，个人偏好让步。
- 新代码与相邻代码保持一致（缩进/命名/结构）。
- 风格冲突时以项目规范为准，并记录取舍。
- 统一工具链与格式化配置，避免人工风格漂移。
