# 自检

边界/架构/状态/异步/命名/模式/测试/类型/反模式检查。

完整版见 `frontend/checklists/detailed-check.md`「适用性判定」。本文件为速查版，措辞与详细版逐条对齐；缺省处以详细版为准。本速查每条仍须按三种结论记录，不适用附一句话原因。

## 清单
### 任务边界（COM-012，不可用"不适用"跳过）
- [ ] 已声明本次授权面；只读档任务全程无写动作。
- [ ] 用户未点名的产物都指出了消费者；无装饰性代码（算了不用、建了不生效、无人读取）。
- [ ] 无范围外扩（未顺手改无关文件、未夹带重构）。
- [ ] 同一事实未重复取证。

### 架构
- [ ] 页面够薄，逻辑在 Logic；且非"把函数搬进 Hook"式达标。
- [ ] 组件职责单一，只做展示与交互，不自取业务数据。
- [ ] Service 唯一接口入口，UI 未直连接口。
- [ ] 依赖只能向下（Page/Component→Hook→Logic→Service；仅允许两类跨层直连，见 `frontend/rules/architecture.md`「规则」），无反向/循环依赖。
- [ ] Logic 层非空转：可判定的业务规则确实落在此层。
- [ ] 单个 Hook ≤150 行、暴露成员 ≤10 个、关注点单一。

### 状态（需刷新保持的状态以 URL 为唯一来源；与 `frontend/protocol/decision-trees.md` 不一致处以 `frontend/rules/store.md` 为准）
- [ ] 状态归属层级正确（局部/父级/URL/Store），范围最小。
- [ ] 状态来源单一，无多写点；受控组件不另存 props 副本。
- [ ] 无冗余派生状态（能算的不存）。
- [ ] 更新走明确 action，无隐藏修改。
- [ ] 组件卸载/重置时状态正确清理，副作用有对应清理。

### 异步与错误
- [ ] try-catch 收敛在统一请求出口，业务方法不重复包裹。
- [ ] 竞态保护真实生效：signal 已下传，并配合序号忽略过期结果。
- [ ] 非幂等请求默认不重试；retryable 被重试逻辑真实消费。
- [ ] 取消（CANCELED）不当作错误态；超时与取消可区分。
- [ ] 刷新失败保留旧数据，不整片清空。

### 其他
- [ ] 命名：动词函数、布尔前缀、无模糊命名。
- [ ] 模式：命中既有 pattern 已套用，未重复造轮子。
- [ ] 测试：关键行为有断言，含边界值与错误路径。
- [ ] 类型：无无理由 any，公共 props/函数有类型定义。
- [ ] 反模式：无 `frontend/examples/golden/anti-examples.md`「1. 页面直接调用 Service」等所列症状复发（见该文件"页面 import Service，并在事件处理里直接发请求 + 手写反馈"）；无装饰性代码（算了不用、建了不生效）。

### 验证（不可用"不适用"跳过；措辞与 `frontend/checklists/detailed-check.md`「测试执行」对齐，缺省处以详细版为准）
- [ ] 构建、类型检查、测试已实际执行并通过。
- [ ] 执行不了时，已按 `common/protocol/final-gate.md`「无法验证时的处理」"禁止默认视为通过"显式声明未验证项与风险。
