# 场景六：职场沟通与函件写作规范（`writing/rules/correspondence.md`）

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

适用范围：正式工作邮件、跨部门协作沟通、全员公告通知、会议纪要、对外商务致函、项目同步消息。
理论底座：美国《2010 年简明写作法案》+ ISO 24495-1:2023 简明语言国际标准 + 英国 GOV.UK 内容设计规范 + 军事与医疗高风险交接 BLUF（结论先行）标准。

## 四条硬性执行标准

### 1. 主题行与首段 10 秒看懂（BLUF 置顶）
- **邮件/公告主题行**：必须自带【动作类型 + 核心事项 + 截止时间】（例：`【需审批】Q3 预算调整方案——请于本周五 17:00 前反馈`），禁止写“关于最近工作的沟通”“请查收”。
- **正文首段（前两句）**：直接亮明写信目的、核心结论与需要收件人做什么；背景说明、历史来龙去脉全部放到正文下半段或附件。

### 2. 行动闭环三要素（谁、做什么、何时截止）
- 凡是需要他人配合、审批、决策或参会的沟通，必须写死三要素：**具体负责人 + 明确动作 + 精确日历日期与时间**（写“11 月 27 日（周四）18:00 前”，不写“尽快 / 下周抽空”）。
- 若涉及多方待办，优先用 3 列紧凑清单（事项 / 负责人 / 截止时间），禁止把 5 个人的任务埋在同一段长文字里。

### 3. 简明直白、去官腔与去双重否定
- 用主动语态和日常短句，删除无意义的公文套话（如“兹定于、特此通知、谨致谢忱、望悉知、原则上不排除”）。
- 禁止双重否定造成误解（写“仅限正式员工申请”，不写“非正式员工不得非经特批申请”）。
- 拒绝或提异议时保持**平实、对事不对人、附替代方案**，不卑不亢，不绕弯子也不带情绪指责。

### 4. 按载体匹配格式
- **正式邮件**：自然短段落 + 清晰问候与署名，不堆砌过多花哨多级标题；正文提及附件或共享文档时，确保已点明链接或附件名称。
- **会议纪要**：严格分为三块——**已拍板结论 / 待办行动清单（含负责人与截止日）/ 待跟进风险与未决项**，严禁逐字记录流水账对话。
- **全员公告**：首句交代“谁受影响、何时生效、需要怎么操作”，其余细则放到 FAQ 或补充说明。

## 禁止事项

- 禁止把真正的请求埋在邮件末尾让收件人翻三屏才看到。
- 禁止发出无明确截止时间、无负责人的模糊待办。
- 禁止用未经翻译的内部缩略语或黑话发给跨部门/外部收件人。
