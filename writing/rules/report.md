# 场景一：报告与方案写作规范（`writing/rules/report.md`）

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

适用范围：工作总结、调研报告、竞品/市场分析、立项方案、战略提案、项目复盘、决策备忘录。
理论底座：麦肯锡金字塔原理（Minto Pyramid）+ SCQA / MECE + 亚马逊六页纸叙事备忘录（6-Pager）+ 美国陆军 AR 25-50（BLUF）。

## 核心结构铁律

### 1. 结论置顶（先给答案，再给证据）
- 报告首页或开篇首段必须给出**一句话核心结论 / 明确建议**（做了什么决定、推荐哪个方案、核心发现是什么、需要谁拍板）。
- 严禁按“我先调研了什么 → 过程经历了什么 → 最后得出结论”的倒叙流水账写报告。

### 2. 开篇用 SCQA 锁定语境
在核心结论之后，用极简四步交代决策背景（不超过半页）：
- **S（背景 Situation）**：各方公认的现状事实（客观、无争议）。
- **C（冲突 Complication）**：打破现状的变化、瓶颈或风险。
- **Q（问题 Question）**：由此引出必须回答的核心问题。
- **A（答案 Answer）**：本文给出的核心判断或推荐方案。

### 3. 论据分组遵守 MECE（相互独立、完全穷尽）
- 支撑主结论的一级分论点控制在 **2–4 个**；每个分论点标题本身必须是一句**有立场的结论句**（如“方案 B 首年总成本低 28%”），而不是空洞标签（如“成本分析”）。
- 同一层级的分论点必须维度一致、互不重叠，不遗漏关键维度（如收益、成本、周期、风险）。

### 4. 完整因果链 + 备选方案对比（借鉴亚马逊 6-Pager）
- 关键判断必须写清**“因为什么事实/数据 → 所以得出什么结论”**，禁止只扔三个孤立要点让读者自己脑补逻辑连接。
- 凡是立项、选型或决策类方案，必须包含**“备选方案对比与否决理由”**（为什么不选其他方案）以及**“最大风险与兜底预案”**。

### 5. 量化优先与收尾行动闭环
- 尽量用可核验的量化指标（金额、周期、转化率、人数、边界条件）替代“显著提升、大幅改善、效果良好”。
- 报告结尾必须落到**可执行动作表**：明确每一项下一步动作的**目标、负责人/角色、预期节点与验收标准**。

## 禁止事项

- 禁止标题只写“背景、现状、分析、总结”这类无信息量的目录壳子。
- 禁止隐藏核心风险或单方面吹捧推荐方案。
- 禁止在同一份报告中把同一组数据在正文、表格、总结里重复说三遍。
