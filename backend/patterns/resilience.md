# 韧性、超时传递与流量治理模式（BE-107）

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 1. 超时与截止时间传递（Deadline Propagation）
- 入口为每个请求设定总超时预算（如 HTTP API 5s–15s），通过 `context.WithTimeout`（Go）或剩余时间计算向下游 DB/RPC/HTTP 传递；下游超时不得超过父请求的剩余预算。
- 外部 HTTP 客户端必须显式配置连接超时、读写超时与最大空闲连接数，严禁使用默认无超时客户端（如 Go `http.DefaultClient`）。

## 2. 出向重试约束
- 仅对**幂等操作**或携带有效 `Idempotency-Key` 的写请求，在网络超时 / `502` / `503` / `504` / `429` 时重试。
- 必须使用**有限次数（通常 ≤ 3 次）+ 指数退避 + 全抖动（Full Jitter）**，且退避休眠必须监听 `ctx.Done()` 及时退出。
- **超时结果未知**：对支付、扣款、发券等非幂等外部调用超时后，禁止盲目重试，必须走「查询状态接口 + 补偿/对账」路径。

## 3. 熔断、降级与多维限流
- **熔断（Circuit Breaker）**：下游错误率或慢调用率超阈值时快速失败（Fast-Fail），进入半开探测恢复，避免雪崩拖死本服务线程/协程池。
- **降级（Fallback）**：非核心依赖（如推荐、积分展示、非关键统计）故障时返回兜底数据并打 `WARN` 日志，不得阻塞主交易链路。
- **多维限流**：公开入口与高成本接口须按 IP / UserID / TenantID / API 维度做令牌桶或滑动窗口限流，触发后返回 `429 Too Many Requests` + `Retry-After`。

## 检查清单

- [ ] 无 `http.DefaultClient` 或无超时外部调用
- [ ] 出向重试仅限幂等/带幂等键请求，带上限、退避抖动且响应上下文取消
- [ ] 非核心下游具备降级策略；高风险入口具备限流与 `429` 响应
