# 缓存工程模式

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 1. Cache-Aside 标准读写与一致性
- **读路径**：先读缓存 → 未命中查 DB → 回填缓存（带 TTL）。
- **写路径**：**先更新数据库（事务提交后），再删除缓存**（优先删除而非回写新值，避免并发写乱序覆盖旧值）。
- 对强一致要求极高的读（如扣款后立即查余额、幂等冲突回读），直接走主库或读源，不读缓存。

## 2. 三大缓存故障防护
- **防穿透（查询大量不存在的 Key）**：入口做参数格式/范围校验；对不存在的 ID 缓存短 TTL 空占位符（如 30–60 秒）或前置布隆过滤器。
- **防击穿（热点 Key 过期瞬间大量并发打穿 DB）**：进程内使用 `singleflight`（Go）或分布式短互斥锁（PHP/跨实例），仅放行 1 个请求回源重建，其余等待或退避重试。
- **防雪崩（大面积 Key 同时过期）**：在基础 TTL 上叠加随机抖动（如 `baseTTL + rand(0, 15%)`），严禁整点批量固定过期。

## 3. Key 规范与大小红线
- Key 命名统一：`{env}:{service}:{domain}:{entity}:{id}`（带版本前缀便于结构变更平滑切换）。
- 单 Value 严禁超过 100KB（防 Redis 大 Key 阻塞单线程）；集合类型严禁无界增长；所有缓存 Key **必须设置 TTL**（除非明确为持久化 KV）。

## 检查清单

- [ ] 写操作在事务提交后删除缓存，而非事务内更新缓存
- [ ] 所有缓存 Key 均设 TTL 且叠加随机抖动防雪崩
- [ ] 热点回源具备 Singleflight 或互斥锁防击穿；空结果有防穿透保护
