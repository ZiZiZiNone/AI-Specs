# 仓储越界

对齐关系见 `backend/go/structure.md`（数据层收敛）与 `backend/php/structure.md`，本文件不自立新约束。

对齐条目：`backend/go/structure.md`「规则」：「dao 封装全部 SQL，logic 不直接操作数据库连接，不拼 SQL 字符串。」；`backend/php/laravel/structure.md`「规则」：「仓储封装全部查询实现，服务禁止直调模型查询构造器。」

## 定义

数据层含业务分支、返回业务语义、回调业务层或互调，即为仓储越界。

## 判定信号

### 可观测信号

- 数据层方法内出现业务状态判断（如"已支付才能查"写在 SQL 组装旁）。
- 仓储返回业务结论而非数据（如返回"是否允许下单"）。
- 仓储调用服务、仓储互调、数据层内自行重试。
- 服务绕开仓储直调模型查询构造器，查询实现两处各写一遍。

### 症状（命中 2 条即进入对策）

- 换一种查询条件需改业务语义，数据层测试必须懂业务规则。
- 同一查询在仓储与服务各实现一遍，结果偶发不一致。
- 数据层无法脱离业务状态单测。

## 对策

- 查询实现全部收敛仓储，服务禁止直调模型查询构造器。
- 业务分支上浮服务层，仓储方法只收过滤结构、只返数据与分页。
- 重试只在服务边界显式决策，仓储内不得自行重试。
- 跨聚合协作见 `backend/php/structure.md`「规则」：「跨聚合协作由服务组合多个仓储，禁止仓储相互调用。」
