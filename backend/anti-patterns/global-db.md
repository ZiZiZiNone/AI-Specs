# 全局数据访问

对齐关系见 `common/principles.md`「模块解耦原则」：依赖显式传入，不隐式获取。本文件不自立新约束。

## 定义

逻辑单元绕过参数与构造函数，直接从全局取连接、配置、日志或当前请求，即为全局数据访问。

## 判定信号

### 可观测信号（引用 `common/principles.md` 原文）

- 「不通过全局单例、全局变量、静态门面」获取依赖：逻辑单元内出现全局数据库句柄、静态门面解析、服务定位器调用。
- 逻辑单元签名只用业务结构：Go 侧禁收 HTTP 对象；PHP 侧禁收传输对象，输入为 DTO 或标量数组。
- 单测必须启动 HTTP 服务或连接真实数据库才能运行。

### 症状（命中 2 条即进入对策）

- 换一个宿主（新入口、单测）需改逻辑内部代码。
- 同一逻辑在并发下互相干扰，状态归属说不清。
- 替换一个依赖（如换日志实现）需改所有调用点。

## 对策

- 连接与客户端经构造函数注入接口，测试用替身替换，见 `backend/go/testing.md`「规则」与 `backend/php/testing.md`「规则」（通用方法见 `common/rules/test.md`「规则」）。
- 配置在启动时集中加载，逻辑单元只接收解析后的配置结构体。
- 日志记录器经参数或构造函数显式传入，不直调全局日志访问点。
- 请求标识由入口生成并透传全链路，下游只透传不重造。
