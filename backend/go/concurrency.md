# Go 并发处理

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `common/principles.md`「极致解耦」与「模块解耦原则」。本文件仅 Go 存在，PHP 不建对应文件。

## 规则

- 并发单元只接收固定结构数据与取消信号，脱离宿主仍可单测验证。
- 共享状态优先用消息传递归拢，确需共享内存时用显式同步原语，边界与持有时长写清注释。
- 并发规模、超时与取消策略显式传入，不在逻辑单元内硬编码协程数，调用方可复现与压测。
- 错误与取消信号向上传递并收敛，子任务失败可取消同批任务，不吞错误不静默丢弃结果。
- 竞态敏感代码必跑竞态检测，临界条件覆盖恰好等于上限的场景，互逆操作有往返一致断言。
- 并发只用于可并行任务，顺序业务规则不拆并发，新增并发需指明消费者与收益依据。

## 检查清单

- [ ] 并发单元可脱离宿主单测
- [ ] 共享状态同步方式明确
- [ ] 规模超时取消显式可配
- [ ] 错误与取消正确上传
- [ ] 竞态检测已执行通过
- [ ] 无为顺序规则强加并发
