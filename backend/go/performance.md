# Go 性能

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `common/principles.md`「逻辑解耦原则」与 `backend/README.md`「分层原则（PHP / Go 共用）」。取舍见 `common/protocol/task-boundary.md`「消费者判据（四问）」。

## 规则

- 先用可复现的基准数据定位热点，再优化，不凭感觉加缓存、池化与并发。
- 热点收敛到逻辑单元或数据层，入口只做组装与转发，不在入口做批量拼装与转换。
- 同一计算与同一查询只实现一份，循环内重复查询合并为批量查询，空结果同样走统一形状。
- 超时、限流、分页上限由服务端显式声明（本库无全局阈值），调用方不自行推导总量。列表形状见 `common/rules/api-contract.md`「分页」。
- 资源复用需指明消费者与生命周期，连接、缓存与大对象池化有上限与释放策略。
- 性能结论附测试命令、数据规模与前后数字，来自构造数据的数字标注来源，不写入正式结论。

## 检查清单

- [ ] 优化前有基准数据定位
- [ ] 热点收敛无入口计算
- [ ] 循环查询已批量化
- [ ] 超时与分页上限已声明
- [ ] 复用资源有上限与释放
- [ ] 性能数字来源可复现
