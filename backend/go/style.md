# Go 代码风格与格式化

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

规范优先依据见 COM-009 `common/rules/constitution.md`：「已有规范覆盖的场景必须遵守规范，不得临时发挥或绕过」。本文件只定 Go 工具链可验证项。

## 规则

- 提交前必跑 `gofmt -l .`、`go vet ./...` 与 `goimports`（或 `gofumpt`），零告警方可合入。
- import 分三段：标准库、第三方、模块内，自动整理。
- 函数超过五十行或圈复杂度超十即拆分（圈复杂度用 `gocyclo` 度量），不靠注释掩盖长函数。数字是职责单一的可观测代理，不是目的：达标但职责混杂仍不合规。
- 导出符号必写注释，未导出复杂逻辑写意图注释。
- 不用空接口透传业务对象，泛型受限在容器与仓储抽象。
- 错误字符串小写无标点，提示文本由上层组装。
