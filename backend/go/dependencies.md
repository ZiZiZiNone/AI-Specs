# Go 依赖管理

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `common/principles.md`「单向依赖原则」与 `backend/README.md`「分层原则（PHP / Go 共用）」。新增依赖取舍见 `common/protocol/task-boundary.md`「消费者判据（四问）」。

## 规则

- 依赖方向唯一向下，控制器依赖服务接口，逻辑实现依赖数据接口，不出现反向与循环引用。
- 对外依赖经构造函数注入接口，不在逻辑单元内直连具体实现，测试可用替身替换。
- 新增第三方依赖先指明直接消费者与替代方案，指不出消费点的依赖不引入。
- 依赖版本以业务项目 `go.mod` 与 `go.sum` 锁定（非规范库路径），升级用 `go list -m all` 与 `go mod tidy` 核对影响面，说明影响范围与回滚方式，不静默放宽版本约束。
- 跨模块复用走服务接口，不直调对方内部实现包，不绕过接口访问数据层。
- 无业务规则的中间转发包直接删除，依据见 `common/principles.md`「单向依赖原则」：「某层删掉后若没有任何业务规则随之丢失，它就不该存在」。

## 检查清单

- [ ] 依赖方向唯一向下无循环
- [ ] 外部依赖均经接口注入
- [ ] 新增依赖均有指明消费者
- [ ] 版本锁定且升级有说明
- [ ] 跨模块调用只走接口
- [ ] 无纯转发包残留
