# GoFrame 测试差异

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `backend/README.md`「现有子目录」与「分层原则（PHP / Go 共用）」。方法见 `common/rules/test.md`「规则」。

## 规则

- 只写框架差异：服务接口与逻辑实现分离测试，逻辑测试不起服务、不走传输层，替身注入数据接口。
- 控制器只测参数绑定与响应形状，业务分支断言下沉服务测试，不在控制器重复覆盖规则。
- 测试数据用明确的数据结构构造，不构造传输对象。
- 关键分支、边界与错误路径必有断言，框架中间件行为用轻量集成测试覆盖，不混入单元测试。
- 执行命令与结果可复现，缺环境按 `common/protocol/final-gate.md`「无法验证时的处理」声明。
- 框架版本升级先重跑全部测试，失败先定位差异点，不为通过而放宽断言。

## 检查清单

- [ ] 逻辑测试脱离宿主运行
- [ ] 控制器只断言边界与形状
- [ ] 输入输出结构明确
- [ ] 边界与错误路径有断言
- [ ] 命令结果可复现或已声明
- [ ] 升级后已全量重跑
