# GoFrame 项目结构与分层落地

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `backend/README.md`「分层原则（PHP / Go 共用）」与 `common/principles.md`「薄入口原则」。方向见 `common/principles.md`「单向依赖原则」。

## 规则

- 目录沿用接口、逻辑实现、数据访问分离，控制器只做绑定、调用与响应，不做业务分支。
- 逻辑单元不接收传输对象，只收结构体与上下文。
- 逻辑单元不自己取数据库连接，数据访问收敛在数据层。
- 依赖经参数或构造函数显式传入，服务实现经构造函数注入数据接口。
- 跨模块调用走服务接口，不直调对方实现包，不绕层访问数据层。
- 无业务规则的中间层直接删除。

## 检查清单

- [ ] 控制器无业务分支
- [ ] 逻辑签名无传输对象
- [ ] 数据访问收敛在数据层
- [ ] 依赖均经构造函数注入
- [ ] 跨模块只走服务接口
- [ ] 无纯转发层残留
