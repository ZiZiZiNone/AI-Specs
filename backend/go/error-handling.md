# Go 错误处理

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `backend/README.md`「分层原则（PHP / Go 共用）」与 `common/principles.md`「逻辑解耦原则」。业务码形态见 `common/rules/api-contract.md`「业务错误码」。

## 规则

- 错误在逻辑单元内构造并分类，入口只做组装与转发。
- 哨兵错误按包集中定义，调用方用错误判定分支，不解析错误文本做流程控制。
- 参数错误、业务失败、系统故障分开表达，业务失败统一映射业务码，不混用传输状态。
- 同一校验与同一失败语义只实现一份，跨模块复用同一逻辑单元。
- 错误上抛保留因果链并追加当前层上下文：每层至多用 `%w` 包装一次并附加层名与字段，禁止 `%v` 丢因果与多层重复 `%w`。
- 错误详情只写日志，返回给调用方的是可执行说明，响应形状见 `common/rules/api-contract.md`「响应信封」。

## 检查清单

- [ ] 入口无错误构造与业务分支
- [ ] 哨兵错误集中且可判定
- [ ] 业务失败均有业务码对应
- [ ] 同一规则无重复实现
- [ ] 错误链完整且上下文充分
- [ ] 返回文本可执行且无内部细节
