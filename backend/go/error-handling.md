# Go 错误处理规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 核心规则

1. **错误必处理，禁静默丢弃**：严禁 `_ = fn()` 忽略可失败操作（`defer resp.Body.Close()` 等少数场景也应按需记录或显式说明）。
2. **因果链包装 `%w`**：跨层向上返回错误时使用 `fmt.Errorf("create order %s: %w", req.Key, err)` 附带业务上下文，同时保留哨兵错误供调用方 `errors.Is` / `errors.As` 判定。
3. **错误日志只记一次**：在同一调用链中，错误要么记录日志并消费，要么包装返回给上层，严禁每层既打日志又返回导致重复告警。
4. **仓储层禁隐藏重试与 SQL 脱敏**：DAO/Repository 如实映射底层错误（如唯一键冲突 → `ErrConflict`、记录不存在 → `ErrNotFound`），不私自重试；SQL 报错日志严禁打印明文敏感绑定参数。
5. **Panic 仅限不可恢复启动期**：业务请求链路严禁主动 `panic` 替代返回 `error`；入口中间件与事务包装器必须用 `defer recover()` 兜底回滚并转为 `500` 响应。

## 检查清单

- [ ] 跨层错误使用 `%w` 保留根因，调用方用 `errors.Is`/`errors.As` 判定
- [ ] 无同一错误在多层重复打 `ERROR` 日志
- [ ] 事务包装器具备 `defer` panic 回滚守卫
