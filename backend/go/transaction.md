# Go 事务与迁移

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `backend/README.md`「分层原则（PHP / Go 共用）」与 `common/principles.md`「薄入口原则」。本文是 `backend/checklists/detailed-check.md`「事务检查」各条的规则源，清单只判结论，不重复本文件。

## 规则

- 事务由服务层经事务闭包显式定界（开启即定界，闭包自动提交与回滚），入口只做组装与转发，不开事务、不决定回滚。
- 数据层方法只收上下文并经上下文取事务，不自己从全局取连接，不双传上下文与事务对象，不私开跨界与嵌套事务。
- 同一业务用例的多表写在一次事务内完成；跨用例不共享事务，跨用例一致性用补偿说明，不用超大事务硬包。
- 失败分支全部回滚，提交前校验已通过，早退路径不漏回滚；唯一冲突后的回读必须在失败事务之外的新读路径执行，默认读已提交，冲突重试预算由业务项目声明。
- 隔离与并发写入风险已评估，以项目实测为准；回填与重放可重复执行，不因重跑产生重复副作用。
- 事务内不调外部网络与长耗时操作；必须调用时超时与补偿已说明。
- 迁移可执行且可回滚，回填脚本幂等；接口破坏性变更的版本策略见 `common/rules/api-contract.md`「版本化」，不与迁移版本混用。

## 检查清单

- [ ] 事务开启点在服务层，入口无事务语句
- [ ] 数据层无全局连接获取与私开事务
- [ ] 失败与早退路径全部回滚
- [ ] 事务内无外部调用，或超时补偿已说明
- [ ] 迁移可执行可回滚，回填幂等
- [ ] 无超大事务，隔离风险已评估
