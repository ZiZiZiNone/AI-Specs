# 后端 Bugfix 任务

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

线上错误、契约偏离、数据不一致、事务与迁移缺陷的根因修复。后端专属。

## 授权面：定向写，限改动点与真实调用链

只写已列明的文件，加上真实调用链上被迫改的文件（见 `common/protocol/task-boundary.md`「只写已列明的文件，加上真实调用链上被迫改的文件」）。

修共享业务、共享仓储、公共错误映射时查所有调用方（见 `common/protocol/task-boundary.md`「修共享函数时必须一并改真实受影响的调用方」）。

加东西前先过消费者四问，判据见 `common/protocol/task-boundary.md`「四问全否 → 不实现，可作为建议报告」。

升档见 `common/protocol/task-boundary.md`「升档必须由用户明确表示」。降档见 `common/protocol/task-boundary.md`「降档不需要授权」。

## 流程：复现→定位→修复→验证

1. 复现：用真实请求、失败用例、日志请求标识稳定复现，确认触发条件与影响面；同一事实取证一次即止。
2. 定位：追根因到分层位置（契约、校验、用例分支、事务边界、查询、迁移），修共享逻辑查所有调用方；疑似分层违规对照 `backend/anti-patterns/` 与 `backend/examples/golden/anti-examples.md`。
3. 修复：最小改动修根因，不夹带重构与契约变更；若为权宜方案需注明有效期与跟进项；迁移修复必须给出回滚路径。
4. 验证：回归验证修复场景与相关调用方；重跑须有理由。

## 规则

- 修复根因不是症状；权宜方案必须注明。
- 不顺手改无关接口、表与配置；四类越界判据见 `common/protocol/task-boundary.md`「四类越界」。
- 引用规范条款前打开原文核对，见 `common/rules/constitution.md`「编号 + 文件路径 + 原文逐字摘录」。
- 报缺口须附检索命令与空结果。
- 同一事实取证一次即止。
- 验证类条目不可跳过，执行不了按 `common/protocol/final-gate.md`「无法验证时的处理」声明。
