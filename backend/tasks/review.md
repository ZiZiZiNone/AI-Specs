# 后端 Review 任务

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

问题、风险、建议、依据。后端专属，只审分层、契约、事务、迁移、安全与可维护性。

## 授权面：只读

全程不修改代码，包括明显的笔误、错字、失效分支与低风险改动。它们写进问题表格，由用户决定是否修。

允许的动作：读文件、检索、执行只读白名单命令、输出报告（指对话内报告）。

只读白名单（仅允许以下只读形式，按项目实际取用）：

- 静态检查：只读形态的静态检查命令（结果摘录粘贴）
- 测试：只读形态的测试命令（结果摘录粘贴；只读执行，不改代码）

构建不在白名单；确需验证构建另起定向写或开放写任务并声明授权面。

禁止的动作：写文件（含把报告落盘成文件）、改写参数、格式化、删除、提交、安装依赖、执行迁移、启动服务、写入远端。未列举但产生文件、依赖、数据或远端变更的命令一律禁止。

报告需落盘时，另起任务并重新声明授权面。

用户在看到报告后要求修改时，任务类型重新判定（改行为走 Bugfix，只调结构走 Refactor），并声明新的授权面。不要在同一轮里边审边改。

判据见 `common/protocol/task-boundary.md`「四类越界」。

## 输出

- 问题：按严重度列出的具体问题（含文件与位置）。
- 风险：潜在缺陷与影响范围（含数据与事务风险）。
- 建议：可执行的改进建议。
- 依据：每条结论给出对应规范与代码依据（文件路径加逐字摘录）。
- 评分（可选）：按四维各 0 至 5 打分，附失分原因。

## 评分标准（每维 0 至 5，总分等于各项均值）

- 架构：入口厚度、分层合规、依赖方向、事务边界。
- 契约：路由与版本、信封与错误码、分页与幂等、兼容性。
- 可维护性：可读性、可测试性、迁移可回滚性、变更成本。
- 安全与数据：鉴权、注入与越权、事务完整性、敏感数据。

## 规则

- 结论有据可查，不做无依据评价。
- 区分确定问题与建议改进。
- 引用规范条款前打开原文核对，见 `common/rules/constitution.md`「编号 + 文件路径 + 原文逐字摘录」。
- 报缺口须附检索命令与空结果。
- 同一事实取证一次即止，见 `common/protocol/task-boundary.md`「同一事实已有足够证据」。
