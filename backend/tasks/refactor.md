# 后端 Refactor 任务

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

分层搬移、命名统一、拆分大业务、查询优化等不改行为的结构调整。后端专属。

## 授权面：定向写，行为不变

只写已列明的文件，加上真实调用链上被迫改的文件（见 `common/protocol/task-boundary.md`「只写已列明的文件，加上真实调用链上被迫改的文件」）。

重构目标之外的接口、表、契约与配置不动；整体重构需用户明确授权升档（见 `common/protocol/task-boundary.md`「升档必须由用户明确表示」）。

不夹带功能改动与契约变更。加东西前先过消费者四问，判据见 `common/protocol/task-boundary.md`「四问全否 → 不实现，可作为建议报告」。降档见 `common/protocol/task-boundary.md`「降档不需要授权」。

## 流程：目标→基线→小步→回归

1. 目标：明确重构目标（分层、命名、拆分、查询），一次只做一件事；分层命名类目标对照 `backend/anti-patterns/` 与 `backend/examples/golden/service-slice.md` 确认目标形态；列明非目标（契约、事务语义、迁移内容不变）。
2. 基线：先补跑测试建基线，记录接口契约基线（状态码、错误码、分页、幂等）与行为基线口径。
3. 小步：小步重构，保持行为不变，每步可回滚；迁移重构先保证可回滚再改结构。
4. 回归：对照基线口径回归验证；重跑须有理由。

## 规则

- 不夹带功能改动与契约变更；每步可回滚；事务语义不变。
- 四类越界判据见 `common/protocol/task-boundary.md`「四类越界」。
- 引用规范条款前打开原文核对，见 `common/rules/constitution.md`「编号 + 文件路径 + 原文逐字摘录」。
- 报缺口须附检索命令与空结果。
- 同一事实取证一次即止。
- 验证类条目不可跳过；执行不了按 `common/protocol/final-gate.md`「无法验证时的处理」声明。
