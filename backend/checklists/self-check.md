# 后端精简自检清单

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

详细版见 `backend/checklists/detailed-check.md`。本文件为精简版，每条缺省处以详细版为准。

## 适用性判定（先做这一步，缺省处以详细版为准）

每条结论填通过或不适用加原因或未通过；禁止把不适用标成通过。验证类与任务边界类无不适用，执行不了按 `common/protocol/final-gate.md`「无法验证时的处理」声明。

## 精简自检（每条缺省处以详细版为准）

- [ ] 授权面已声明且未自行升档（结论：<通过或未通过>）
- [ ] 改动在需求范围或真实调用链上（结论：<通过或未通过>）
- [ ] 无装饰性产物（结论：<通过或未通过>）
- [ ] 同一事实未重复取证，已列出已读规范与触发依据（结论：<通过或未通过>）
- [ ] 交付文本无无决策用途的免责与过程叙述（结论：<通过或未通过>）
- [ ] 入口够薄，分层单向向下，业务可测（结论：<通过或不适用加原因或未通过>）
- [ ] 接口契约明确（路由、信封、错误码、分页、幂等、版本；缺省处以详细版契约章为准）（结论：<通过或不适用加原因或未通过>）
- [ ] 错误统一归一，无吞错与信息泄漏（结论：<通过或不适用加原因或未通过>）
- [ ] 事务边界与回滚完整，迁移可回滚（结论：<通过或不适用加原因或未通过>）
- [ ] 无循环内查询，分页与索引对照已做，非幂等默认不重试（结论：<通过或不适用加原因或未通过>）
- [ ] 鉴权、注入、脱敏、密钥无问题（结论：<通过或不适用加原因或未通过>）
- [ ] 日志分级与请求标识完整，无敏感数据（结论：<通过或不适用加原因或未通过>）
- [ ] 配置走环境，必填快速失败，无幽灵配置（结论：<通过或不适用加原因或未通过>）
- [ ] 依赖清单一致，无多余重型依赖（结论：<通过或不适用加原因或未通过>）
- [ ] 注释写为什么，无死代码（结论：<通过或不适用加原因或未通过>）
- [ ] 并发：仅 Go；PHP 写明不适用（结论：<通过或不适用加原因或未通过>）
- [ ] 拿不准处已查决策树、模式与示例（结论：<通过或不适用加原因或未通过>）
- [ ] 构建、静态检查、测试已实际执行并记录命令与结果（结论：<通过或未通过>，未执行按 `common/protocol/final-gate.md`「声明模板」填）
