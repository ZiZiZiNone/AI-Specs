# PHP 目录结构与分层

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。见 `<SPEC_ROOT>/README.md`「路径基准」。

基准见 `backend/README.md`「分层原则（PHP / Go 共用）」与 `common/principles.md`「逻辑解耦原则」。

## 规则

- 控制器只解析输入、调用服务、返回资源，禁止业务判断与模型直调。
- 服务承载全部业务规则，输入为 DTO 或标量数组，输出为 DTO 或模型无关结构。
- 聚合指一组内聚的业务规则与其归属的数据，一个聚合对应一仓；Go 侧同一业务用例视同同一聚合边界。
- 仓储封装查询实现，一个聚合一仓，禁止业务分支。
- 模型只定义关系、转换与查询作用域，禁止业务方法。
- 依赖经构造函数显式传入。
- 表单请求只做校验与授权，不做业务转换；转换归服务。
- 跨聚合协作由服务组合多个仓储，禁止仓储相互调用。

## 检查清单

- [ ] 控制器无业务判断与直接查库
- [ ] 服务输入输出与传输对象无关
- [ ] 仓储无业务分支
- [ ] 模型无业务规则
- [ ] 依赖方向唯一向下
- [ ] 无纯转发服务
