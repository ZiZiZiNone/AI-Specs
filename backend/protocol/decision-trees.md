# 决策流程图

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

将后端复杂判断转化为明确的决策流程。分层唯一来源见 `backend/README.md`「分层原则（PHP / Go 共用）」。

## 一、分层落位决策

### 决策流程
```
开始：一段新逻辑要落位
  ↓
问：是否为路由、参数绑定、响应封装？
  ├─ 是 → 入口（控制器），无业务分支
  └─ 否 ↓
问：是否为业务判断、规则计算、事务边界？
  ├─ 是 → 业务层（Go 的 logic / Laravel 的 Service），可脱离宿主单测
  └─ 否 ↓
问：是否为 SQL、查询组装、持久化细节？
  ├─ 是 → 数据层（Go 的 dao / Laravel 的 Repository），上层不拼 SQL
  └─ 否 ↓
问：删掉它是否有业务规则随之丢失？
  ├─ 否 → 不该存在，直接删除（见 `common/principles.md`「单向依赖原则」：「某层删掉后若没有任何业务规则随之丢失，它就不该存在。」）
  └─ 是 → 重新审视前三问，必有其一命中
```

### 示例对照
| 需求 | 落位 | 原因 |
|---|---|---|
| 订单金额计算与优惠叠加规则 | 业务层 | 业务判断，可单测 |
| 按状态过滤订单的查询组装 | 数据层 | 持久化细节 |
| 把业务结果装进响应信封 | 入口 | 组装与转发 |
| 转发调用不做任何判定 | 删除 | 无规则丢失即为纯转发层 |

## 二、事务边界决策

### 决策流程
```
开始：一次写操作
  ↓
问：是否只写单表且无跨表一致性要求？
  ├─ 是 → 不开事务
  └─ 否 ↓
问：多表写是否属同一业务用例？
  ├─ 否 → 拆用例或用补偿说明，不用超大事务硬包
  └─ 是 ↓
落位：服务层显式开启（Go 见 `backend/go/transaction.md`「规则」；PHP 见 `backend/php/transaction.md`「规则」）
  ↓
问：事务内是否必须调用外部网络或长耗时操作？
  ├─ 是 → 超时与补偿已说明，否则移出事务
  └─ 否 → 通过
```

### 判定标准
- 开启与回滚语义以语言规则源为准：Go 见 `backend/go/transaction.md`「规则」；PHP 见 `backend/php/transaction.md`「规则」。
- 迁移可执行且可回滚，回填脚本幂等，见对应语言 `transaction.md`「检查清单」。

## 三、重试与幂等决策

### 决策流程
```
开始：一次出向调用或写接口
  ↓
问：是否为读操作（GET 类查询）？
  ├─ 是 → 允许重试，带退避与上限，取消到达即中断
  └─ 否 ↓
问：是否为 POST 类非幂等写？
  ├─ 是 → 默认不重试（见 `common/rules/api-contract.md`「幂等与重试」：「`POST` 禁自动重试」）
  └─ 否（PUT / DELETE）→ 按业务项目声明决定，默认不假设可重试
    ↓
问：需防重放吗？
  ├─ 是 → 调用方生成幂等键，服务端按键去重并声明去重窗口（见 `common/rules/api-contract.md`「幂等与重试」：「调用方生成 `Idempotency-Key`，服务端按键去重」）
  └─ 否 → 人工确认后重发，不自动重试
    ↓
同一幂等键重复提交返回首次结果，不执行第二次副作用。
```

### 示例对照
| 场景 | 判定 | 原因 |
|---|---|---|
| 列表查询超时 | 退避重试 | 读操作无副作用 |
| 创建订单超时 | 不自动重试 | 重试会重复创建资源 |
| 支付回调重复送达 | 按键去重，返回首次结果 | 防重放 |

## 四、复用抽象决策

### 决策流程
```
开始：发现重复代码
  ↓
问：这是第几处出现？
  ├─ 第 1 处 → 直接实现，不抽象
  └─ 第 2 处及以上 ↓
问：两处需求是否完全一致且抽象后更简单？
  ├─ 否 → 保持重复，等第三处或明确共性
  └─ 是 ↓
落位：下沉到被调用业务或数据层，不在入口复制分支（见 `backend/checklists/detailed-check.md`「分层检查」：「跨业务复用下沉到被调用业务或数据层，不在入口复制分支」）
  ↓
替换所有调用点，不留重复实现。
```

### 判定标准
- 新增抽象、依赖、配置项先过消费者判据，见 `common/protocol/task-boundary.md`「消费者判据（四问）」：指不出消费点视同全否。
- 标准库优先，无为单函数引入重型依赖。

## 检查清单

- [ ] 落位结论明确，无向上与反向依赖
- [ ] 事务开启点唯一且在服务层
- [ ] 非幂等写默认不重试，需去重的已声明幂等键
- [ ] 复用下沉到位且替换了全部调用点
- [ ] 拿不准的框架专属点已提问而非自行发挥
