# 最终闸门

> 路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

输出前必须通过检查。

## 检查
- 对照**对应子树**的自检清单逐项自检（前端：`frontend/checklists/self-check.md`「自检」："边界/架构/状态/异步/命名/模式/测试/类型/反模式检查"），
  覆盖边界 / 架构 / 状态 / 异步 / 命名 / 模式 / 测试 / 类型 / 反模式）。
- 完整交付前另过对应子树的详细清单（前端：`frontend/checklists/detailed-check.md`「适用性判定」："每条只有三种结论——通过 / 不适用（附原因）/ 未通过"），
  先做「适用性判定」再逐项给结论。
- 关键数据与数字有来源或可复现；来自 mock 的数字须标注（见 `common/rules/test.md`「Mock 与假数据」："交付文档中若引用了 mock 产生的数字，必须标注来源为 mock"）。
- 约束未越界、需求已覆盖、产物可运行/可打开。越界的判定标准见 `common/protocol/task-boundary.md`「四类越界」："需求是一个点，动作扩成一片"等四类形态（授权面三档与四类越界：范围外扩 / 无消费者产物 / 意图越界 / 重复取证）。
- 验证通过才算完成，未过项明确列出。

## 验证要求
- 涉及代码的任务必须实际执行构建/类型检查/测试，不以"读代码没问题"替代执行。
- 执行命令与结果需可复现（记录命令本身，而非仅结论）。
- **要求是至少执行一次，不是执行多次**：一次通过即为已验证。重跑须有理由
  （改动后需重验、上次执行环境不同）；无理由的反复重跑属重复取证，见 `common/protocol/task-boundary.md`。

## 无法验证时的处理
环境不具备执行条件时（沙箱不可用、缺少依赖、无权限等），禁止默认视为通过。必须：

1. 明确声明哪些验证项**未执行**（构建 / 类型检查 / 测试 / 运行）。
2. 说明无法执行的具体原因（错误信息或环境限制）。
3. 给出可复现的验证命令，供用户在本机补跑。
4. 在交付结论中标注"未验证"，不得表述为"已完成/已通过"。

**禁止**：以静态推演结果冒充执行结果；用"应该可以运行"这类措辞填充验证结论。

## 声明模板
```
未验证项：<命令1>、<命令2>（原因：<具体报错或环境限制>）
补跑命令：cd <目录> && <安装依赖> && <验证命令>
已完成项：<实际执行过的检查>
```

各端验证命令示例（按项目实际取用，不照抄）：

- 前端：`npm run typecheck`、`npm run test`、`npm run build`
- Go：`go build ./...`、`go vet ./...`、`go test ./...`
- PHP：`composer install`、`vendor/bin/pest`（或 `phpunit`）、`vendor/bin/pint --test`
