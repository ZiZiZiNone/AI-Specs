# 复用与抽象规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 抽象决策

1. **三法则（Rule of Three）**：
   - 第 1 次出现：直接就地实现，任何情况下不为"未来可能"预造抽象（参见 `common/protocol/task-boundary.md`「消费者判据（四问）」）。
   - 第 2 次出现：允许适度重复，观察两处是否同源演进。
   - 第 3 次出现且确认属**本质重复**：再抽取共享模块。
2. **区分本质重复 vs 偶发重复**：
   - **本质重复**：表达同一业务规则或同一技术协议（如订单金额计算、统一请求信封解析）——应当复用，避免改一处漏两处。
   - **偶发重复**：仅当前字段/代码结构碰巧相似，但分属不同业务域、未来独立演进（如“用户表单”与“供应商表单”）——**严禁强行合并**，否则演进时互相牵制。
3. **过度抽象红灯信号（出现即应拆分）**：
   - 为适配不同调用方，共享函数/组件引入 **≥ 3 个布尔标志位参数**（如 `isAdmin`, `hideFooter`, `skipCheck`）；
   - 共享函数内部出现针对特定调用方名称的条件分支（`if (caller === 'pageA')`）；
   - 抽取后调用点代码量与理解成本高于保留两份直观实现。

## 检查清单

- [ ] 新建公共模块均有 ≥ 2 个真实活跃消费者，无预造抽象
- [ ] 已确认抽离的是本质重复而非偶发结构相似
- [ ] 公共函数/组件未出现 ≥ 3 个布尔开关或按调用方硬编码分支
