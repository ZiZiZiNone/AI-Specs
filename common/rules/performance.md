# 通用性能规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

端专属性能细则见 `frontend/rules/performance.md`、`backend/go/performance.md`、`backend/php/performance.md`、`backend/patterns/caching.md`。

## 核心原则

1. **先正确后优化**：不以牺牲数据一致性、可读性或安全性为代价做无依据微优化。
2. **先测量后优化（强制基线）**：任何以“性能优化”为目标的变更，必须在提交说明中附带**优化前/后量化数据**（如 P95/P99 延迟、QPS、SQL 次数、内存峰值、Bundle 体积、LCP/INP）及可复现的测量命令，禁止凭感觉“觉得这样更快”。
3. **热点优先**：通过 Profiler（`pprof` / DevTools Performance / 慢查询日志）定位真实瓶颈，优先优化高频路径与数量级复杂度（O(n²) → O(n) / 消除 N+1）。

## 通用性能红线（无需压测即可直接拦截）

- **禁循环内 I/O（N+1）**：禁止在 `for`/`map` 循环内逐条发起数据库查询、RPC 或 HTTP 请求；必须批量查询（`IN` / 批接口）或聚合预加载。
- **禁无界查询与无界返回**：所有列表查询、导出、批量任务必须有分页、条数上限或流式/分批游标处理，禁止 `SELECT *` 全表拉入内存。
- **所有外部调用必设超时**：HTTP、RPC、DB、Redis、队列调用必须设置显式超时，禁止无限等待拖垮连接池。
- **所有内存缓存必设上限与过期**：进程内缓存（Map/LRU）必须有最大容量（Max Entries/Bytes）与 TTL，禁止无界增长导致 OOM。

## 检查清单

- [ ] 优化类 PR 附带优化前/后量化对比数据与复现方式
- [ ] 无循环内 DB/HTTP/RPC 调用（N+1）
- [ ] 所有列表与批处理均有硬上限或流式分块
- [ ] 全部外部 I/O 均有显式超时，全部内存缓存均有容量上限与 TTL
