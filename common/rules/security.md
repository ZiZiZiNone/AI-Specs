# 通用安全基线（COM-013 细则）

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

本文件为 `COM-013` 的端无关安全基线。前端细则见 `frontend/rules/security.md`，后端细则见 `backend/patterns/authz-security.md`、`backend/go/security.md`、`backend/php/security.md`。

## 1. 认证与鉴权（默认拒绝）
- 所有受保护接口与资源默认拒绝访问，仅对显式声明公开的端点（如登录、健康检查）放行。
- 严格区分三层边界：**认证（你是谁）**、**粗粒度功能权限（你能调这个接口吗）**、**细粒度资源归属（你能操作这条数据吗，防 IDOR/BOLA）**。前端隐藏按钮只是交互优化，后端必须做最终鉴权。

## 2. 输入校验与输出编码
- **所有外部输入不可信**（Query、Body、Header、Cookie、上传文件、第三方 Webhook、甚至数据库历史脏数据），必须在入口做类型、长度、范围与白名单校验。
- **按输出上下文防注入**：SQL 一律参数化查询（禁字符串拼接）；HTML 渲染一律自动转义或经权威白名单净化；Shell 命令禁直接拼接用户输入；文件路径拼接须校验规范化后仍位于允许根目录内（防路径穿越 `../`）。

## 3. 密钥与凭证全生命周期
- 严禁将 API Key、私钥、数据库密码、JWT Secret、OAuth Client Secret 硬编码进源码、注释、配置文件或测试用例（可用明显假值如 `test-dummy-secret-not-real` 并加测试注释）。
- 密钥通过环境变量或密钥管理服务注入；仓库仅提交不含真值的 `.env.example`。
- 疑似密钥泄露入 Git 历史时，第一时间吊销并轮换凭证，而非仅删除文件了事。
- 密码存储必须使用现代抗暴力算法（Argon2id / bcrypt），禁止 MD5 / SHA1 / 无盐 SHA256；会话令牌与 API Token 落库须存哈希值。

## 4. 最小权限与敏感数据分级
- 数据库账号、云 IAM 角色、Token 作用域严格遵循最小权限原则，禁止业务服务使用超级管理员账号运行。
- 敏感数据（身份证、银行卡、手机号、凭证）传输须全链路 TLS，存储按合规要求加密或脱敏，响应按需裁剪字段（禁止整表对象直出给前端）。

## 检查清单

- [ ] 全部受保护端点均默认拒绝，且包含资源归属（防越权）检查
- [ ] 无 SQL/HTML/Shell/路径穿越拼接漏洞
- [ ] 通过 `scripts/check-security-hygiene.py` 扫描，零硬编码密钥与高危模式
- [ ] 响应 DTO 已裁剪内部字段与敏感信息
