# 业务规则建模与归属规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

本文件细化 `common/principles.md`「3. 逻辑解耦原则」，适用于前端 `logic/` 与后端 `service/` / `domain/`。

## 四条判定规则

1. **唯一权威源（Single Source of Truth）**：同一业务规则（如订单是否可取消、优惠券适用门槛、折扣计算、权限判据）在单端只允许一处权威实现，严禁在入口层、UI 组件库配置、表格列渲染与提交函数中各写一份。
2. **展示格式化 vs 领域规则**：
   - **展示格式化**（日期本地化显示、千分位加逗号、截断省略号、状态徽章配色）：归属展示/视图适配层，不改变业务语义。
   - **领域规则**（状态机合法跃迁、价格/税费/优惠计算、库存扣减资格、数据归属权判定、表单跨字段校验）：业务规则进入Logic。必须归属纯逻辑层或后端领域服务，并由后端做最终权威裁决（前端校验仅用于即时反馈，不可替代服务端校验）。
3. **状态机显式建表**：涉及 3 个及以上状态流转的实体（如订单 `pending → paid → shipped → completed / canceled`），必须用显式跃迁表（Transition Map）定义合法前置状态与目标状态，禁止用散落各处的 `if (status !== 'a' && status !== 'b')` 拼凑。
4. **金额与高精度计算禁浮点**：金额、费率、清结算严禁使用二进制浮点数（IEEE 754 `float`/`double`/`number` 小数）直接加减乘除；统一使用最小货币整数单位（如分 `int64`）或定点数库（`Decimal`），舍入策略（如半偶舍入/向下取整）必须显式声明。

## 正反对照

- ❌ 反例：在前端模板写 `v-if="order.status === 1 && Date.now() - order.createdAt < 1800000"`，同时在后端 Controller 再写一遍超时判断，且用 `price * 0.85` 浮点算折后价。
- ✅ 正例：后端领域服务提供权威 `CanCancel(order, now)` 与 `ApplyDiscountCents(amountCents, rateBps)`；前端纯函数 `canShowCancelAction(order, now)` 仅做同口径展示判断且可独立单测。

## 检查清单

- [ ] 核心业务规则均有唯一权威实现，无入口/组件/服务多处复制
- [ ] 状态流转通过显式跃迁表或集中校验函数约束
- [ ] 金额与清结算计算未使用裸浮点数
- [ ] 前端校验均有对应的后端权威校验兜底
