# 通用测试规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 规则

1. **测行为不测实现细节**：断言输入到输出的契约、状态变化与外部可观测副作用，不绑定内部私有方法名或临时变量。
2. **命名表达场景与预期**：测试命名必须清晰描述「被测单元 + 场景/条件 + 预期结果」。具体标识符形态遵守各语言惯例：
   - TypeScript / JavaScript / PHP：可用 `should_<expected>_when_<condition>` 或清晰自然语言用例描述；
   - Go：必须遵守 `go test` 语法要求，采用 `Test<Unit>_<Scenario>_<Expected>`（如 `TestOrderCreate_RejectsExpiredCoupon`）。
3. **边界、异常与互逆断言**：除正常路径外，必须覆盖空值、上下界临界点（`0`/`-1`/`max`/`max+1`）、非法输入、错误回滚与并发/重放；凡序列化与解析配对函数（如 URL Query 编解码），必须写互逆断言。
4. **测试确定性与隔离**：单元测试严禁依赖真实系统时间、未固定种子的随机数、外部网络或用例执行顺序；每个用例独立构造与清理数据。
5. **测试必须实际执行**：改完代码后必须实跑测试套件；环境无法执行时按 `common/protocol/final-gate.md` 声明未验证项，禁止凭空宣称“测试通过”。

## Mock 与假数据

- **前端替身**：Mock 数据与内存假实现集中在独立 mock 目录（如 `src/services/mock/`），仅通过依赖注入或环境开关接入，严禁混入生产业务代码。
- **后端替身**：优先使用实现仓储/客户端接口的轻量内存 Fake（如 `MemoryOrderRepository`），其次才是行为 Stub；严禁为追求覆盖率去 Mock 被测单元自身的内部方法。
- **强制标注红线**：
  - 交付文档中若引用了 mock 产生的数字（README / 验收报告 / 结论），必须标注来源为 mock
  - 禁止将 mock 数据伪装为真实线上压测或生产统计结果（`COM-007`）。

## 检查清单

- [ ] 测试命名清晰包含被测单元、条件与预期，且符合目标语言测试框架语法
- [ ] 覆盖正常路径、临界值、异常回滚与幂等/并发场景
- [ ] 无外部网络、真实时钟或用例顺序依赖
- [ ] 交付文档中所有源自 mock 的数据均已显式标注来源
- [ ] 测试命令已实际执行并记录结果（或按 `common/protocol/final-gate.md` 声明未验证）
