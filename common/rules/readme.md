# 业务项目 README 规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

本规范约束业务项目根目录的 `README.md`（与本规范库 `<SPEC_ROOT>/README.md` 区分）。

## 必载八项

1. **项目简介与边界**：一句话说明做什么、不做什么。
2. **目录结构**：顶层关键目录及职责说明。
3. **技术栈与版本**：语言、核心框架、包管理器与最低运行时版本。
4. **环境与配置**：环境变量清单（引用 `.env.example`，**严禁写入真实密钥**）。
5. **本地启动**：从零安装依赖到跑起服务的完整可复制命令。
6. **构建、检查与测试**：构建、Lint、类型检查、单测命令及通过判据。
7. **部署与发布入口**：构建产物说明、迁移步骤或 CI/CD 指针。
8. **待办与已知限制**：项目级未完成事项与风险说明（行级技术债锚点可用 `TODO(owner/#issue)` 留在代码处，见 `common/rules/comment.md`）。

## 组织与禁令

- 根 `README.md` 必须作为唯一总入口；中大型项目可建 `docs/` 存放 ADR、OpenAPI 或运维手册，但须在根 `README.md` 中索引挂载，禁止出现无人知晓的孤立文档。
- 禁止在 README 中粘贴真实密钥、内网密码、生产数据库连接串或未脱敏的客户数据（`COM-013`）。
- 禁止写无法执行的过期命令；凡修改启动/测试脚本时须同步更新 README。
- 禁止用营销口号替代可执行的工程说明。

## 检查清单

- [ ] 必载八项齐全且命令经实测可执行
- [ ] 环境变量通过 `.env.example` 说明，无任何真实密钥泄露
- [ ] 若存在 `docs/` 子文档，均已在根 `README.md` 建立清晰索引
