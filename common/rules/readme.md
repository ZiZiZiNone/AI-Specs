# 项目 README

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析，首段为 `common/`、`frontend/` 或 `backend/`。
见 `<SPEC_ROOT>/README.md`「路径基准」。

项目根目录的 `README.md` 必须完整记录**所有需要人工操作和使用的说明**。
代码能自解释的部分不重复，人工必须知道的部分不得省略。

## 规则

- 位置固定：项目根目录 `README.md`，不另建 `docs/` 分散入口。
- 面向读者是**接手项目的人**（同事、未来的自己），不是作者。
- 命令必须**可直接复制执行**，含工作目录；不写"按需配置"这类空话。
- 环境差异必须写明，不假设读者与作者环境一致。
- README 与代码同步：改动安装方式、配置项、部署流程时，同一次提交内更新 README。
- 未完成事项写进 TODO，不散落在代码注释与聊天记录里。

## 必载内容

| 章节 | 至少包含 |
|---|---|
| **目录结构** | 逐目录说明用途；标注哪些目录是生成物、哪些不要手改 |
| **安装** | 依赖版本与安装命令；前置条件（运行时版本、系统依赖、外部服务） |
| **配置** | 全部配置项及其含义、取值范围、默认值；敏感项说明来源，**不写真实密钥** |
| **运行** | 开发模式启动命令；端口；健康检查或验证方式 |
| **开发到生产的配置与部署变化** | 逐项列出开发与生产**不同**的配置（数据库、缓存、日志级别、队列驱动、调试开关等）；部署步骤；构建产物形态；回滚方式 |
| **测试** | 测试命令、测试范围、需要的外部依赖（如测试库） |
| **常见问题** | 已踩过的坑与对应解法；报错信息 → 原因 → 处理 |
| **TODO** | 未完成事项、已知缺陷、待决策项；每条注明影响面 |

## 禁止

- 只写项目名与一句简介，把安装配置留给读者猜。
- 配置项写一半（如只列 `.env` 里的名字，不说明取值与默认值）。
- 用"开发环境见 xxx、生产环境另行配置"代替具体差异清单。
- TODO 写成愿望清单（"优化性能"），不写具体位置与影响面。
- 把密钥、口令、内网地址明文写进 README。
