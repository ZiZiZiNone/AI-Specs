# 通用注释规范

路径基准：本文所有裸路径相对规范库根 `<SPEC_ROOT>` 解析。见 `<SPEC_ROOT>/README.md`「路径基准」。

## 核心规则

1. 注释写"为什么这么做"，不写"这行做了什么"。：代码本身已清晰表达步骤时禁止写复述型注释（如 `// i 加 1`）；注释只解释非显而易见的业务背景、权衡理由、不变量、外部协议怪癖或性能妥协。
2. **导出契约注释与实现注释分离**：
   - 公共导出的模块、接口、领域函数必须具备契约注释（GoDoc / PHPDoc / JSDoc），说清前置条件、副作用、错误语义与并发安全性。
   - 函数内部仅对复杂算法、边界假设或反直觉代码加简短行内注释。
3. **可追踪的 `TODO` / `FIXME` / `HACK` 格式**：必须带负责人与追踪单号及退出条件，例如 `TODO(alice/#1248): 订单表迁移完成后删除双读分支`；禁止无主、无单号、永久悬空的 `// TODO: fix later`。
4. **严禁死代码注释与墓碑注释**：废弃代码直接删除（历史交给 Git），禁止整段注释掉保留；修错后按 `AGENTS.md` `FE-005` 删净，禁止写 `// 旧逻辑已删除` 类墓碑注释。
5. **严禁敏感信息入注释**：禁止在注释中写入真实密钥、测试账号密码、内网生产 IP 或真实客户信息（`COM-013`）。

## 正反对照

- ❌ 反例：`// 遍历订单计算总价`（复述代码）；`// TODO: 优化这里`（无主无单号）；`// oldPrice := calcOld(x)`（死代码注释）。
- ✅ 正例：`// 微信支付回调可能乱序到达，此处必须校验状态机前置条件以防已退款订单被回写为已支付`。

## 检查清单

- [ ] 无复述代码字面含义的废话注释
- [ ] 所有导出公共接口与复杂不变量具备清晰契约注释
- [ ] 所有 `TODO`/`FIXME` 均附负责人与 Issue 编号
- [ ] 无被注释掉的死代码与墓碑注释，无敏感凭证信息
