# 最终闸门

输出前必须通过检查。

## 检查
- 对照 checklists/self-check.md 逐项自检（架构/状态/异步/命名/模式/测试/类型/反模式）。
- 完整交付前另过 checklists/detailed-check.md，先做「适用性判定」再逐项给结论。
- 关键数据与数字有来源或可复现；来自 mock 的数字须标注（见 rules/test.md）。
- 约束未越界、需求已覆盖、产物可运行/可打开。
- 验证通过才算完成，未过项明确列出。

## 验证要求
- 涉及代码的任务必须实际执行构建/类型检查/测试，不以"读代码没问题"替代执行。
- 执行命令与结果需可复现（记录命令本身，而非仅结论）。

## 无法验证时的处理
环境不具备执行条件时（沙箱不可用、缺少依赖、无权限等），禁止默认视为通过。必须：

1. 明确声明哪些验证项**未执行**（构建 / 类型检查 / 测试 / 运行）。
2. 说明无法执行的具体原因（错误信息或环境限制）。
3. 给出可复现的验证命令，供用户在本机补跑。
4. 在交付结论中标注"未验证"，不得表述为"已完成/已通过"。

**禁止**：以静态推演结果冒充执行结果；用"应该可以运行"这类措辞填充验证结论。

## 声明模板
```
未验证项：npm run typecheck、npm run test（沙箱未启动，原因：<具体报错>）
补跑命令：cd <目录> && npm install && npm run typecheck && npm run test
已完成项：<实际执行过的检查>
```
